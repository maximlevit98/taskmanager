# Задачи контента

Первый рабочий срез: регистрация, проект бренда, участники и роли.

Роли в проекте:

- **Владелец** создаёт проект и назначает остальных.
- **Участник** готовит материалы.
- **Согласующий** один на проект. Без его «да» пост не выходит.
- **Публикатор** выкладывает пост вручную.

Если участника ещё нет в системе, на его почту остаётся приглашение. После регистрации с этой почтой проект появляется сам.

## Запуск

Порт на хосте **3010**. Порт 3000 не используется.

```bash
docker compose up --build
```

Открыть http://localhost:3010

Локальные пароль базы и секрет сессии в `docker-compose.yml` только для этого запуска.

## Сессии

Для разработки Compose явно задаёт `SESSION_MODE=local-http` и публикует порт только на 127.0.0.1. Открывайте приложение по http://localhost:3010. При запуске через `npm run dev` передайте те же переменные сессии, что указаны в Compose.

Для production запустите образ за HTTPS-прокси. Передайте `SESSION_MODE=https` (это режим по умолчанию), рабочий `DATABASE_URL` и `SESSION_SECRET` через хранилище секретов окружения. Создайте ключ командой `openssl rand -hex 32`. Все экземпляры приложения должны получать один ключ; его замена завершает ранее выданные сессии. Порт приложения должен быть доступен только прокси. Локальный Compose предназначен для разработки.

При старте сервер проверяет режим и ключ до обращения к базе. В HTTPS-режиме cookie `session` получает атрибуты `Secure`, `HttpOnly`, `SameSite=Lax` и `Path=/`. В локальном HTTP-режиме снимается только `Secure`. Выход устанавливает пустую cookie с теми же атрибутами и `Max-Age=0`.
