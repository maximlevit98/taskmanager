# Задачи контента

Первый рабочий срез: регистрация, проект бренда, участники и роли.

Роли в проекте:

- **Владелец** создаёт проект и назначает остальных.
- **Участник** готовит материалы.
- **Согласующий** один на проект. Без его «да» пост не выходит.
- **Публикатор** выкладывает пост вручную.

Владелец приглашает человека по почте. И новому, и существующему пользователю нужно войти с приглашённым адресом и ввести код из письма на странице `/invites`. Код действует 24 часа. Владелец может отменить приглашение или отправить новый код, который заменит старый. Для новых приглашений доступны участник и публикатор. Если прежнее приглашение указывает на роль согласующего или фактическая роль отличается от приглашённой, адрес остаётся подтверждённым, а роль выбирает владелец.

## Запуск

Порт на хосте **3010**. Порт 3000 не используется.

```bash
docker compose up --build
```

Открыть http://localhost:3010

Локальные пароль базы и секрет сессии в `docker-compose.yml` только для этого запуска.

## Доставка приглашений

Передайте приложению `INVITE_SMTP_URL` (например, `smtps://USER:PASSWORD@smtp.example.org:465`), `INVITE_FROM` (подтверждённый отправитель) и `APP_PUBLIC_URL` (публичный HTTPS-адрес приложения). Для SMTP с STARTTLS используйте `smtp://USER:PASSWORD@HOST:587/?requireTLS=true`. Спецсимволы логина и пароля в URL закодируйте. Настройте отправляющий домен у почтового провайдера.

Для локальной проверки укажите SMTP-приёмник, например Mailpit, доступный из контейнера приложения. При недоступной почте владелец видит ошибку и может повторить отправку. Тесты используют только локальный SMTP-приёмник.

При переходе на новую версию остановите старые экземпляры приложения перед запуском новых: старый обработчик регистрации выдавал членство по одному адресу. Новая схема сохраняет прежние приглашения без действующего кода. Владелец отправляет письмо из списка приглашений. Действующие участники сохраняют роли.
